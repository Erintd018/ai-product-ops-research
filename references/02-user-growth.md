# 用户分析与增长诊断 · 舆情方法论 · 口碑采集 · PLG 诊断

> Agent 2（用户分析与增长诊断）的专业认知参考。涵盖舆情采集方法、情感分析、AARRR 框架、用户旅程诊断、PLG 成熟度评估。

## 1. 社媒运营拆解框架

### 平台逐一拆解维度

每个平台分析：

- 账号基础数据（粉丝量、发布频率、活跃度）
- 内容类型分布（图文/短视频/直播/长文/互动帖）
- 爆款内容特征（主题、形式、钩子、互动量）
- 人设与语气（官方严肃/亲切活泼/技术极客/生活化）
- 发布节奏（日更/周更、时间规律）
- 互动运营（评论区运营、置顶内容、粉丝互动）

### 内容策略归纳

- **内容支柱（Content Pillars）**：产品教程/用户案例/行业洞察/品牌故事/UGC 转发/热点借势
- **形式矩阵**：图文、短视频（15s/60s/3min）、直播、长视频、图集、互动投票
- **人设定位**：品牌官号 vs 创始人 IP vs 产品小助手 vs 用户社区

### 增长打法分析

- 拉新钩子（免费额度/邀请奖励/限时活动/爆款内容引流）
- 转化路径（内容→关注→私域→试用→付费）
- KOL/达人合作模式（付费投放/产品置换/联合创作/官方体验官）
- 活动玩法（挑战赛/创作大赛/节日营销/联名）
- 社群运营（Discord/微信群/即刻圈子）

### 衡量指标

- 互动率（点赞+评论+转发/粉丝数）
- 涨粉速度与趋势
- 爆款率（超均值 3x 的内容占比）
- Share of Voice（品牌声量占行业比）
- 内容传播深度（二次传播/UGC 衍生）

## 3. 舆情分析方法论

### 评论采集源

- 应用商店：App Store（分区）/ Google Play / 各安卓市场
- B端口碑站：G2 / Capterra / TrustRadius
- 社区：Reddit / 知乎 / V2EX / 即刻 / Hacker News / Product Hunt
- 社媒评论区：X / 小红书 / B站弹幕+评论 / 微博

### 情感分析框架

**主题编码**（按产品特性调整）：

- 核心功能/效果
- 性能/速度
- 价格/性价比
- 易用性/上手难度
- 客服/售后
- 隐私/安全
- 稳定性/Bug
- 对比竞品

**情感打分**：

- 正面 / 中性 / 负面 三分类
- 强度：强烈（明确推荐/愤怒）/ 一般（满意/不满）/ 轻微（提及/建议）
- 情感净值 = (正面数 - 负面数) / 总样本数

### 痛点与爆点提炼

- **痛点**：用户最常抱怨什么、流失原因、未满足需求
- **爆点**：用户最常被种草什么、Aha Moment、主动推荐理由
- **争议点**：引发两极评价的功能/事件

### 口碑趋势分析

- 版本发布前后的评分变化
- 重大事件后的舆情波动
- 长期趋势（月度/季度口碑走向）
- 竞品同期口碑对比

### 样本偏差识别

- 应用商店评论偏极端（满意/愤怒）
- 社区活跃用户≠全体用户（偏专业/重度）
- 水军/刷评识别（短时间大量雷同评论）
- 分析时显式标注样本来源、数量、偏差

## 3.5 从公开评论中提取用户体验信号

> 用户画像、旅程、留存等数据属于内部指标，无法直接获取。但公开评论中藏着大量"准内部"信号——用户在抱怨什么、在什么环节卡住、为什么离开、为什么付费。本节指导 Agent 3 从舆情数据中系统性提取这些信号，作为策略产出的用户侧核心输入。

### 3.5.1 用户旅程信号提取

从评论中识别用户在不同旅程阶段的体验反馈，按 AARRR 环节分类：

| 旅程阶段 | 提取什么 | 典型信号词/模式 | 信息源偏好 |
|----------|---------|---------------|-----------|
| **认知（Acquisition）** | 用户从哪里知道这个产品、第一印象 | "看到推荐"、"朋友介绍"、"刷到"、"搜到的" | 小红书、知乎、Reddit、Product Hunt |
| **注册/上手（Activation）** | 新用户的上手体验、首次使用障碍 | "注册后不知道干什么"、"一开始很懵"、"上手有点难"、"第一次用就被惊艳" | 应用商店评论、社区新手帖 |
| **核心体验（Aha Moment）** | 用户体验到核心价值的时刻 | "原来可以这样用"、"试了XX功能才觉得值"、"用来做XX之后离不开了" | 种草帖、深度测评、UGC |
| **留存/习惯（Retention）** | 持续使用的原因、日常使用场景 | "每天都用"、"已经离不开"、"用了X个月" | 长期用户评论、社区深度帖 |
| **流失（Churn）** | 为什么离开、转用竞品的原因 | "卸载了"、"退订了"、"换成XX了"、"续费太贵"、"效果不如以前" | 差评、竞品对比帖、退订讨论 |
| **付费（Revenue）** | 付费决策、性价比判断 | "值不值得买"、"Pro值吗"、"免费够用"、"付了但后悔" | 应用商店评论、知乎/Reddit 讨论 |
| **推荐（Referral）** | 主动推荐行为和推荐理由 | "推荐给同事了"、"安利"、"必装"、"强推" | 种草帖、社区推荐帖 |

**提取方法**：
1. 在情感分析的主题编码阶段，增加「旅程阶段」标签（与情感主题正交，不替代）
2. 每条评论可同时标注情感主题（如"性能"）和旅程阶段（如"激活"）
3. 统计各阶段的正负面信号占比，识别旅程瓶颈

### 3.5.2 用户分群信号识别

从评论的语言特征和关注点差异，推断用户群体结构：

| 用户类型 | 识别特征 | 运营含义 |
|----------|---------|---------|
| **技术型用户** | 提及 API、模型名、参数调优、对比技术细节 | 重视文档/社区/开发者关系 |
| **轻度/尝鲜用户** | "试了一下"、"不知道怎么用"、评论短且浅 | 需要场景化引导和新手教程 |
| **重度/付费用户** | 提及具体工作流、长期使用感受、深度功能反馈 | 核心用户群，关注留存和满意度 |
| **被迫迁移用户** | "XX涨价了所以来试"、"XX关了只能用这个" | 需要降低迁移摩擦 |
| **B端/团队用户** | 提及团队协作、管理后台、权限、部署 | 需要企业版功能和支持 |

### 3.5.3 服务质量信号提取

AI 产品的"服务质量"有其独特维度，需从评论中专门提取：

| 维度 | 提取内容 | 运营价值 |
|------|---------|---------|
| **输出质量/准确性** | "回答不准"、"幻觉严重"、"生成的代码跑不通"、"翻译质量下降" | 模型能力 → 影响留存和口碑的核心因素 |
| **响应速度** | "太慢了"、"等半天"、"比XX快多了" | 基础体验 → 影响日常使用意愿 |
| **稳定性/可用性** | "经常崩"、"服务器挂了"、"高峰期用不了" | 工程质量 → 影响信任 |
| **额度/限制** | "免费额度太少"、"用完了很难受"、"限制太多" | Token 经济设计 → 影响转化 |
| **客服/支持** | "没人回"、"工单很慢"、"文档找不到" | 服务运营 → 影响付费用户满意度 |
| **版本变化感知** | "更新后变好了/变差了"、"新版不如旧版" | 模型升级的用户感知管理 |
| **预期落差** | "宣传的效果和实际差太远"、"演示很酷但实际很笨" | 营销一致性 → 影响信任和留存 |

### 3.5.4 运营可行动洞察的产出要求

Agent 3 在完成上述提取后，需在报告中产出以下可直接支撑策略的结论：

1. **旅程瓶颈诊断**：基于各阶段的正负面信号占比，判断用户旅程的最大卡点在哪（是上手难？是核心价值不清晰？是付费转化？还是留存衰减？）
2. **Aha Moment 假设**：从正面评论中提取用户感受到核心价值的典型时刻和功能，形成"激活定义假设"（如：Cursor 的 Aha Moment 可能是"第一次用 Tab 补全完成一段完整函数"）——标注为「假设，需内部数据验证」
3. **流失原因 TOP 3**：按频次排序的流失/退订原因，区分可运营解决的（如教育不足）和需产品/技术解决的（如模型质量）
4. **付费驱动力与阻力**：用户为什么愿意付费？为什么不愿意？免费档是否"太好"或"太烂"？
5. **服务质量评级**：基于上述 7 个维度的综合评级（好/中/差），对比竞品
6. **预期落差分析**：营销承诺与实际体验的差距在哪，是否存在"营销过度 → 体验失望"循环

> ⚠️ 所有涉及内部指标的结论（如激活率、留存率、转化率）必须标注为「基于公开评论推断的假设，需内部数据验证」，不可呈现为事实。

## 4. 关键词体系

每次研究需构建关键词矩阵：

| 类型 | 示例 | 用途 |
| --- | --- | --- |
| 品牌词 | 产品名中英文、缩写、别称 | 舆情监控、社媒搜索 |
| 竞品词 | 核心竞品名 | 竞品对比搜索 |
| 场景词 | "AI写作"/"AI编程助手" | 用户需求搜索 |
| 功能词 | 核心功能名 | 功能评价采集 |
| 情感词 | "好用"/"难用"/"推荐"/"避雷" | 口碑过滤 |
| 事件词 | "发布"/"更新"/"合作"/"融资" | 事件追踪 |

关键词需中英文双语版本，覆盖境内外平台。

### 关键词矩阵生成指南

#### 两阶段生成

关键词矩阵分两阶段构建，避免在竞品未经分析确认前预设竞品词：

**Phase 1 · 初始矩阵（Orchestrator 在 Agent 1 之前生成）**

仅生成以下类型，供 Agent 1 使用：
1. **品牌词**：从 Product Discovery 阶段获取产品正式名称、英文名、常见缩写、别称、公司名
2. **场景词**：从产品定位中提取核心使用场景，转化为用户搜索时会用的自然语言表达
3. **功能词**：从产品官网/文档提取核心功能名称
4. **情感词**：固定词库 + 根据产品特性增补（如 AI 产品常见的「幻觉」「准确率」）
5. **事件词**：固定词库，无需每次调整
6. **扩展**：为每个关键词增加同义词、缩写、常见拼写错误

> ⚠️ 此阶段**不生成竞品词**。Agent 1 使用品牌词 + 场景词进行竞品发现和测绘。

**Phase 2 · 补全矩阵（Agent 1 产出后，Orchestrator 补全）**

Agent 1 确认核心竞品（≤5 个）后：
1. **竞品词**：基于 Agent 1 产出的核心竞品列表，提取各竞品的品牌名、英文名、缩写、别称
2. 将补全后的完整矩阵传入 Agent 2/3/4

#### 关键词覆盖率自检

- [ ] 品牌词是否包含中英文、缩写、别称
- [ ] 场景词是否反映真实用户使用场景（而非产品自己的营销话术）
- [ ] 中英文版本是否均已生成
- [ ] （Phase 2 后）竞品词是否覆盖 Agent 1 认定的所有核心竞品
- [ ] （Phase 2 后）搜索结果是否能覆盖主要竞品和使用场景

## 5. 品牌搜索可发现性（SEO + GEO）

### 传统搜索可发现性（SEO）

- Google/百度搜品牌名，首页是否被产品官网占据
- 品牌名唯一性：裸词搜索是否会被其他含义淹没（如"秒哒"被时间单位"秒"干扰）
- 搜索引擎品牌词竞价情况

### AI 搜索可发现性（GEO）

- **检测方法**：在 Perplexity / ChatGPT / Kimi / Gemini 中提问同类产品推荐（如"有哪些AI应用生成器"），观察目标产品是否被提及
- **AI 推荐排序**：在回答中的位次（首位推荐 vs 中部列举 vs 尾部提及 vs 完全未出现）
- **竞品 GEO 对比**：同一问题下各竞品被 AI 提及的频率和位次
- **GEO 影响因素**：官网结构化数据、高质量对比内容、权威媒体报道覆盖、开源社区存在感

### 诊断输出

- 品牌名消歧难度评级（高/中/低）
- SEO 可发现性评级
- GEO 可发现性评级
- 与竞品的可发现性差距
- 改善建议（SEO 侧 + GEO 侧）

## 6. 采集原则

- **运营+口碑一体采集**：每个平台同时看官方运营数据和用户口碑，不分两步
- **同一产品合并视角**：境内版和境外版视为同一产品，分别在对应平台采集后合并呈现（如"境内社媒运营情况"+"境外社媒运营情况"）
- **精确搜索**：品牌名加引号精确匹配，必要时加公司名/品类限定词
- **标注时效**：所有互动数据标注采集日期
